# Android 分支测试与发版

开发分支为 `joaquinker`，Flutter 项目位于仓库根目录。以下命令在仓库顶层运行。

## 有签名密钥的 Windows 电脑

1. 在此分支修改代码。更新 `pubspec.yaml` 的版本名与递增的内部构建号，并写好 `releases/v版本号-stable/更新说明.md`。
2. 运行 `python ci/android-release.py build`。该命令运行测试、构建并验证三个签名 APK，结束后清理本次临时产物。
3. 提交并推送分支。仅在准备发行时，为这次提交创建与版本名完全一致的新标签，如下例。请将示例版本替换为实际版本：

```powershell
git push origin joaquinker
git tag v0.1.3
git push origin refs/tags/v0.1.3
python ci/android-release.py publish
```

发布命令自动读取版本号并核对 Gitee 标签与当前提交，交互式隐藏输入有发行权限的 Gitee 令牌。也可通过受保护的环境变量 ZLIB_RELEASE_TOKEN 提供。已有 v0.1.2 发行版会触发保护。后续自动创建的 Release 若上传中断，可在同一主机、同一提交重跑 publish。已上传附件将下载校验，同名文件内容冲突时停止。签名成品、SHA-256 和私有调试符号缓存在用户目录的 .zlib-release-cache 下，请保留该目录以支持重试。

构建工具为 Flutter 3.47.9、可用的 Android SDK（含 build-tools 36.0.0）、与本项目 Gradle 兼容的 JDK、Python 3.9+、Git、curl、PowerShell 7。ANDROID_HOME 指向 SDK。签名脚本读取 ZLIB_KEY_DIR 或用户目录的 .android/z-lib-release，使用与稳定版相同的四份签名材料。密钥和符号仅在受信任的签名主机上保存。

## Gitee Go 自动触发

在仓库的 Gitee Go 服务中启用自定义流水线，并从 joaquinker 分支加载 .workflow/android-check.yml 和 .workflow/android-release.yml。分支测试使用云端 GCC 构建容器拉取指定版本的 Flutter，不需要签名材料。

标签发布使用 shell@agent 插件。需在 Gitee Go 注册受信任的 Linux 签名构建机，并把发布流水线的 hostGroupID 配置为实际主机组 ID（配置中的名称为 android-release）。在构建机上安装上述工具、配置 Git 私库只读凭据，以及发布进程可用的 ZLIB_RELEASE_TOKEN、ANDROID_HOME 和签名目录。请限制该主机组的使用者及发行标签的创建权限。

推送 joaquinker 分支时运行测试。推送 v主版本.次版本.修订号 标签时，发布主机检出对应提交，验证其属于 joaquinker 的历史，再运行测试、分架构构建、正式签名、创建 Release、上传三个 APK 和 SHA256SUMS.txt 并回读校验。请选用本地发布或主机组自动发布中的一种执行同一标签。

[触发规则](https://help.gitee.com/gitee-go/pipeline/trigger/) · [主机组 Shell 步骤](https://help.gitee.com/gitee-go/plugin/shell/)
