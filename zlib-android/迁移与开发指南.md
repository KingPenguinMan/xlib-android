## 2. 推荐迁移方式：复制源码和 Git 历史

关闭正在运行的构建。用资源管理器将整个项目复制到移动硬盘或新电脑，开启“显示隐藏项目”，确保包含 `.git`。

必须保留：

- `.git/`（提交、分支、标签）、`.gitignore`、`.metadata`。
- `lib/`、`assets/`、`android/`。
- `pubspec.yaml`、`pubspec.lock`、`analysis_options.yaml`。
- `README.md`、`LICENSE`、本文档。
- `android/gradlew`、`android/gradlew.bat`、`android/gradle/wrapper/gradle-wrapper.jar` 和 `gradle-wrapper.properties`。

可以跳过 `build/`、`.dart_tool/`、`android/.gradle/`、`android/.kotlin/`、`.idea/`，它们会重新生成。APK 可单独保留供安装比较；它不能代替源码。`.workbuddy/` 可作为私人笔记保留，无需参与构建。

复制后的两份项目不会自动同步，后续应明确在哪一份修改。

### 额外制作 Git 备份

在旧电脑 PowerShell 执行：


Bundle 只包含已提交的历史和引用，不包含未提交修改、本文档（提交前）、未跟踪笔记、APK、签名或被忽略文件。需要完整迁移时，同时复制工作目录。


## 4. 首次初始化

进入新电脑的项目目录。删除复制过来的生成缓存（仅上述缓存目录），或运行 `flutter clean`；不要删除源码和 `.git`。

用编辑器修改 `android/local.properties`，把旧路径替换成新电脑路径，推荐正斜杠：

```properties
sdk.dir=D:/Dev/Android/Sdk
flutter.sdk=D:/Dev/flutter
```

Flutter 会更新其余生成属性，此文件不应提交到 Git。

```powershell
flutter clean
flutter pub get
flutter analyze
```

保留 `pubspec.lock`，迁移时先不要运行 `flutter pub upgrade`，避免迁移与依赖升级同时发生。检查 `flutter analyze` 的错误级别；原版本曾有 27 条 info 级提示，不等于构建错误。

如果采用纯 Git/bundle 克隆，优先从旧目录复制三个被忽略的 Gradle 启动文件。Flutter 构建也可能补齐 wrapper；若仍缺失，可在独立临时目录用同版本 Flutter 创建 Android 模板，并仅复制 wrapper 启动文件。不要在现有项目上直接重建 Android 目录，以免覆盖 Kotlin 原生实现和 Manifest。

## 5. 开发和设备测试

```powershell
flutter devices
flutter run -d <设备ID>
```

真机开启开发者选项和 USB 调试，连接后允许调试授权。雷电模拟器先开启 ADB；端口以模拟器设置显示的端口为准，不假设固定端口。

```powershell
adb devices
adb shell getprop ro.product.cpu.abilist
```

ARM64 手机使用 ARM64 包；x86_64 模拟器应使用匹配架构的包。可直接 `flutter run` 让 Flutter 选择设备构建目标。

## 6. 打包与版本号

先确定一个尚未使用、并且大于设备已安装版本的 versionCode。旧发布包可能使用过命令行覆盖的构建号；不要只根据 `pubspec.yaml` 的 `+1` 判断。

以下是示例，`6000` 必须按现有 APK 的 versionCode 核对后再使用：

```powershell
flutter build apk --release --target-platform android-arm64 --build-name 0.1.2 --build-number 6000
```

产物：`build/app/outputs/flutter-apk/app-release.apk`。

单独给 x86_64 模拟器构建：

```powershell
flutter build apk --release --target-platform android-x64 --build-name 0.1.2 --build-number 6000
```

第二次构建可能覆盖同名输出，先把 ARM64 产物复制成独立文件名。也可使用 `--split-per-abi` 生成分架构产物，但该方式可能影响最终 versionCode，发布前要检查 APK 元数据。

使用 SDK 工具核对：

```powershell
apkanalyzer manifest version-name <APK路径>
apkanalyzer manifest version-code <APK路径>
apksigner verify --print-certs <APK路径>
adb install -r <APK路径>
```

这些工具位于 Android SDK 的 Command-line Tools / Build-tools 目录，若不在 PATH，使用完整路径执行。

## 7. 换电脑最容易遗漏的签名问题

当前 `android/app/build.gradle.kts` 明确使用 `signingConfigs.getByName("debug")` 签署 Release。新电脑自动生成的 debug key 通常与旧电脑不同，即使包名相同，也不能直接覆盖安装旧 APK。

若要继续覆盖旧版本，必须找回实际签署旧 APK 的密钥，安全传输到新设备，并核对证书 SHA-256。常见位置为用户目录的 `.android/debug.keystore`，也可能受 Android 用户目录配置影响；本次未在当前用户默认位置确认到该文件，不能假设密钥已随项目迁移。

可以在旧电脑已配置好环境后运行 `android/gradlew.bat signingReport`，查看实际密钥路径及证书。只在自己机器查看，不公开密码、私钥或密钥文件。

长期发布应配置专用 Release keystore，并单独备份密钥和密码。切换到新密钥后通常无法覆盖此前 debug 签名的安装，需规划用户数据迁移。卸载旧应用会清除应用内部账户和设置，不能把卸载当作无损修复。

## 8. 日常修改与回退

文件职责：`main.dart` 为入口与导航，`screens.dart` 为页面，`widgets.dart` 为公共组件，`controller.dart` 管理状态，`api.dart` 负责请求，`domain.dart` 为模型，`native.dart` 为原生桥接；Android 侧的下载和文件操作位于 `MainActivity.kt`。

修改前先 `git status`。完成一版后检查 diff、分析、构建、设备验证，再保存版本：

```powershell
git diff
git add <本次修改的文件>
git commit -m "描述本次改动"
git tag -a v0.1.2 -m "描述版本内容"
```

不要复用已经发布的版本标签。Git 标签、文件名和包内版本需要分别维护；建议统一更新 `pubspec.yaml` 并检查页面里硬编码的版本文字。

查看旧版（先提交或妥善保存当前修改）：

```powershell
git switch --detach v0.1.0
git switch main
```

如要在保留历史的情况下撤销“一起读书”修改：`git revert 348daec`。这会创建新的回退提交。不要用 `reset --hard` 来尝试解决迁移问题。

## 9. 故障排查

| 现象 | 检查方向 |
| --- | --- |
| Dart SDK 版本不满足 | 更换包含兼容 Dart 的 Flutter，单独安装 Dart 不能替换 Flutter 内置 Dart |
| flutter.sdk / sdk.dir 找不到 | 更新新机器的 local.properties |
| Gradle 启动脚本不存在 | 恢复被 Git 忽略的 wrapper 文件 |
| Maven、Gradle、pub 下载失败 | 检查新电脑网络、代理及相应下载源；复制项目不包含完整离线缓存 |
| 构建内存不足 | 当前 Gradle 最大堆 8G、元空间 4G；小内存设备可适当调低，但需重试验证 |
| CPU 不匹配 | 检查设备 ABI 与 APK 的 lib 架构 |
| 覆盖安装失败 | 核对签名、applicationId、versionCode |
| 构建成功但搜索失败 | 这是服务连通性/账户/接口问题，需要另外检查，不能由编译成功证明 |

## 稳定版签名与构建

本次稳定版使用版本名 0.1.2、内部构建号 6009。发布时使用 releases/v0.1.2-stable 下的产物。后续更新继续递增 pubspec.yaml 的内部构建号。

在项目根目录运行以下 PowerShell 命令。将变量替换为待发布的实际版本及构建号。

```powershell
$version = '0.1.2'
$buildNumber = 6009
flutter build apk --release --split-per-abi --obfuscate "--split-debug-info=build/private-symbols/$version-$buildNumber" --extra-gen-snapshot-options=--strip
if ($LASTEXITCODE) { throw 'Flutter build failed' }
./scripts/sign-stable.ps1 -Version $version
Copy-Item build/app/outputs/mapping/release/mapping.txt "build/private-symbols/$version-$buildNumber/"
```

私下备份用户目录下的 .android/z-lib-release 整个目录，其中包括正式密钥、口令、旧签名密钥和轮换证明。换机后恢复到同一相对位置，或通过脚本的 -KeyDirectory 参数指定位置。请勿把签名材料添加到源代码仓库或公开归档。Android 9 及以上使用轮换后的正式签名，更早的受支持系统使用旧签名。请为每个版本单独备份 build/private-symbols 中的映射和符号，以便排查崩溃。
